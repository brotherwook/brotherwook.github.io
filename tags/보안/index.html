[Linux] SSH 로그인 실패 잠금, common-auth 말고 faillock.conf로

왜 갈아엎게 됐나 “SSH 로그인 N번 실패하면 계정을 잠근다"는 기능을 관리용 웹 UI에서 켜고 끄게 만들어야 했다. 기존 구현을 보니 웹 서버가 /etc/pam.d/common-auth 파일을 직접 텍스트로 편집하고 있었다. 처음엔 “되긴 되네” 했는데, 뜯어볼수록 이건 그냥 두면 안 되는 코드였다.. 결국 구조를 통째로 바꿨고, 그 과정에서 배운 걸 정리한다. common-auth를 직접 건드리면 안 되는 이유 /etc/pam.d/common-auth를 런타임에 편집하는 방식은 문제가 한둘이 아니었다. ① common-auth는 SSH만이 아니라 모든 걸 잠근다. 이 파일은 PAM을 쓰는 모든 서비스 공통이다. 여기에 잠금을 걸면 SSH뿐 아니라 sudo, su, 콘솔 로그인, cron까지 다 영향을 받는다. “SSH만 잠그려던” 의도와 범위가 완전히 어긋난다. ...
