Pipefail

[Bash] set -euo pipefail 함정 — rm과 apt가 조용히 스크립트를 죽일 때

rm 한 줄에서 스크립트가 죽었다 set -e가 걸린 셸 스크립트가 자꾸 특정 줄에서 멈췄다. 그 줄은 rm이었다. 원인은 단순했다. rm -f가 아니라 그냥 **rm**을 썼는데, 지울 대상이 없으면 rm은 에러(종료 코드 1)를 낸다. set -e는 그 non-zero를 보고 거기서 스크립트를 끝내버린다. 파일이 늘 있을 줄 알았는데, 어떤 실행 경로에선 없었던 것. 1 2 rm /tmp/state.lock # 파일이 없으면 → rm: cannot remove ...: No such file or directory → exit 1 → set -e 로 종료 rm -f /tmp/state.lock # -f 면 없어도 조용히 exit 0 해결은 -f 하나였다. rm -f(그리고 rm -rf)는 대상이 없어도 종료 코드 0이라 set -e에 안 걸린다. “없으면 그냥 넘어가기"가 목적이면 rm엔 습관적으로 -f를 붙이는 게 맞다. ...
