[RTSP] IP만 알면 RTSP 주소를 자동으로 — ONVIF GetStreamUri

카메라 IP만 알고 RTSP 경로는 모를 때. 카메라마다 다른 rtsp URL을 손으로 넣는 대신 ONVIF GetStreamUri로 자동으로 받아오는 법. Media2/Media1 폴백과 계정 삽입까지.

손으로 RTSP 주소를 넣고 있었다#

앞서 RTSP를 몇 번 다뤘는데, 정작 기본에서 걸리는 게 하나 있었다. **“카메라 IP는 아는데 RTSP 주소를 모른다”**는 상황이다.

RTSP 경로는 제조사마다, 심지어 같은 제조사 모델마다 제각각이다. rtsp://ip:554/Streaming/Channels/101 인 놈도 있고 rtsp://ip/live/main 인 놈도 있고.. 이걸 다 외우거나 매뉴얼을 뒤질 순 없다. 그래서 처음엔 카메라 등록 화면에서 사람이 직접 RTSP 주소를 타이핑하게 해뒀다. 카메라 하나 늘 때마다 주소를 찾아 넣는 게 여간 번거로운 게 아니었다.

결론부터 말하면, IP + 계정만 있으면 RTSP 주소는 자동으로 받아올 수 있다. ONVIF를 지원하는 카메라라면(요즘 IP 카메라는 대부분 된다) GetStreamUri 한 방이면 끝난다.

ONVIF가 뭔데#

ONVIF는 IP 카메라·NVR 같은 영상 장비들이 제조사가 달라도 서로 통신할 수 있게 만든 표준 인터페이스다. SOAP 기반이라 살짝 구식 냄새는 나지만, “카메라에 표준 방식으로 이것저것 물어볼 수 있다"는 게 핵심이다. 그중 미디어 서비스에 “네 스트림 주소 뭐야?“라고 묻는 GetStreamUri 가 있다.

파이썬이면 onvif-zeep(혹은 그 계열) 라이브러리를 쓰면 된다. 흐름은 이렇다.

  1. IP·포트·계정으로 ONVIFCamera 객체를 만든다
  2. 미디어 서비스를 생성한다
  3. GetProfiles()로 프로파일(주/보조 스트림 등) 목록을 받는다
  4. 각 프로파일 토큰으로 GetStreamUri()를 호출해 RTSP 주소를 얻는다

Media2 → Media1 폴백이 필요하다#

여기서 한 가지 함정. ONVIF에도 버전이 있어서, 최신 카메라(Profile T)는 Media2 서비스를 쓰고 파라미터 형식이 다르다. 반면 기존 카메라 대부분은 Media1이다. 그래서 Media2를 먼저 시도하고, 안 되면 Media1로 떨어지게 짜는 게 안전하다.

from urllib.parse import urlsplit, urlunsplit
from onvif2 import ONVIFCamera   # onvif-zeep 계열

def probe_rtsp(ip, user, pwd, port=80, wsdl_dir=None, embed_cred=True):
    """IP + 계정으로 카메라의 RTSP URI 목록을 얻는다. -> [(profile_name, uri), ...]"""
    cam = ONVIFCamera(ip, port, user, pwd, wsdl_dir, adjust_time=True)
    results = []

    try:
        # Media2 (ONVIF Profile T, 최신 카메라)
        media2 = cam.create_media2_service()
        for p in media2.GetProfiles():
            uri = media2.GetStreamUri({'Protocol': 'RtspUnicast',
                                       'ProfileToken': p.token})
            results.append((p.Name, uri))
    except Exception:
        # Media1 폴백 (대부분의 기존 카메라)
        media = cam.create_media_service()
        for p in media.GetProfiles():
            r = media.GetStreamUri({
                'StreamSetup': {'Stream': 'RTP-Unicast',
                                'Transport': {'Protocol': 'RTSP'}},
                'ProfileToken': p.token,
            })
            results.append((p.Name, r.Uri))

    if embed_cred:
        results = [(n, _with_cred(u, user, pwd)) for n, u in results]
    return results

두 API의 GetStreamUri 파라미터 형태가 다른 게 보일 거다. Media2는 Protocol: 'RtspUnicast', Media1은 StreamSetup에 Stream/Transport를 중첩해서 넘긴다. 이거 때문에 “코드가 왜 어떤 카메라에선 되고 어떤 건 안 되지” 하고 헤매기 쉬운데, 버전 차이라는 걸 알면 폴백으로 깔끔하게 처리된다.

GetStreamUri 결과엔 계정이 안 들어있다#

또 하나 놓치기 쉬운 점. GetStreamUri가 돌려주는 주소는 보통 rtsp://<ip>:554/... 형태로 계정(user:pass)이 빠져 있다. 그대로 플레이어에 넣으면 401이 난다. 그래서 받은 URI에 계정을 끼워 넣어주는 처리가 필요하다.

def _with_cred(uri, user, pwd):
    """rtsp://host/... -> rtsp://user:pass@host/... 로 계정을 넣어준다."""
    s = urlsplit(uri)
    if '@' in s.netloc or not user:
        return uri          # 이미 들어있거나 계정이 없으면 그대로
    return urlunsplit((s.scheme, f'{user}:{pwd}@{s.netloc}',
                       s.path, s.query, s.fragment))

⚠️ 계정을 URL에 박아 넣는 건 편하지만, 로그나 화면에 그대로 노출되기 쉽다. 화면에 보여줄 땐 비밀번호를 마스킹하고, 실제 연결에만 쓰도록 분리하는 걸 권한다.

참고: IP도 모를 때 — WS-Discovery#

“IP조차 모르고 네트워크에 어떤 카메라들이 있는지부터 알고 싶다"면 ONVIF의 WS-Discovery가 있다. 같은 네트워크에 멀티캐스트로 “거기 ONVIF 장비 있니?“를 뿌리면 장비들이 자기 주소를 응답한다. wsdiscovery 같은 라이브러리로 장비 IP 목록을 먼저 수집하고, 거기에 위 probe_rtsp를 돌리면 “네트워크 스캔 → RTSP 주소 자동 수집” 파이프라인이 된다. (다만 멀티캐스트라 네트워크 환경에 따라 안 잡히는 경우도 있어서, IP를 아는 상황이면 그냥 위 방식이 제일 확실하다.)

정리#

  • 카메라마다 다른 RTSP 경로를 손으로 넣지 말고, **ONVIF GetStreamUri**로 자동으로 받아오자.
  • Media2 먼저, 안 되면 Media1 폴백 — 파라미터 형식이 다르다.
  • 결과 URI엔 계정이 빠져 있으니 user:pass@ 를 끼워 넣어야 한다. 단 노출 주의.
  • IP도 모르면 WS-Discovery로 장비부터 찾을 수 있다.

카메라 등록 화면에서 RTSP 주소 입력란을 없애고 “IP·계정 넣으면 알아서 채워지게” 바꾸고 나니, 카메라 늘릴 때마다 매뉴얼 뒤지던 일이 사라졌다. 사소해 보여도 운영 편의는 확 올라간 변경이었다.
