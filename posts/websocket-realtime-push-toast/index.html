[WebSocket] 서버가 브라우저로 실시간 알림 push하기 — msg_type 라우팅과 스택 토스트

서버에서 이벤트가 생길 때마다 브라우저 화면 구석에 잠깐 띄우는 실시간 알림. 하나의 소켓으로 여러 종류 이벤트를 나르는 msg_type 라우팅, 아이템마다 개별 타이머를 두는 스택 토스트, 그리고 Python 테스트 클라이언트.

서버 이벤트를 브라우저에 실시간으로 띄우고 싶다#

서버에서 어떤 일이 생길 때마다(이미지가 하나 만들어졌다든가) 그걸 브라우저 화면에 실시간으로 잠깐 띄우고 싶었다. 화면 구석에 작게, 최신 것이 위로 쌓이면서 몇 초 뒤 사라지는 그런 알림.

폴링(주기적으로 서버에 물어보기)으로도 되지만, “생기는 즉시"가 중요하면 WebSocket이 맞다. 서버가 연결된 브라우저로 먼저 밀어(push) 줄 수 있으니까. 만들면서 정리한 것들을 적어둔다.

하나의 소켓, 여러 종류의 이벤트 — msg_type 라우팅#

실시간 채널을 열면 곧 여러 종류의 메시지가 오간다. 이미지 알림, 상태 변경, 하트비트.. 이걸 소켓마다 따로 열지 말고, 하나의 소켓에 메시지 종류를 실어 보내는 게 깔끔하다. 그래서 메시지에 항상 msg_type 필드를 둔다.

{ "msg_type": "image", "img_path": "/data/sample.jpg", "channel": 3 }

socket.onmessage = (e) => {
  const data = JSON.parse(e.data);
  switch (data.msg_type) {
    case "image":
      if (typeof onImage === "function") onImage(data);  // 이 페이지에 핸들러가 있을 때만
      break;
    case "status":
      onStatus(data);
      break;
    // 새 이벤트는 여기 한 줄씩 늘리면 된다
  }
};

여기서 typeof ... === "function" 가드가 유용했다. 소켓 연결 코드는 모든 페이지 공통으로 두고, onImage 같은 핸들러는 그게 필요한 페이지에서만 정의하는 식이다. 그러면 알림을 띄울 화면에서만 그 case가 실제로 동작하고, 다른 페이지에선 조용히 무시된다.

스택 토스트 — 핵심은 “아이템마다 개별 타이머”#

화면에 띄우는 부분. 요구는 이랬다.

  • 최신 알림이 아래에 쌓이고, 기존 건 위로 밀린다
  • 최대 5개까지만, 넘으면 가장 오래된 것 제거
  • 각 알림은 3초 뒤 자동으로 사라짐
  • 마우스를 올리면 × 버튼이 떠서 3초 전에 직접 닫을 수 있음

여기서 제일 중요한 게 **“타이머를 하나로 두지 말고, 아이템마다 따로 둔다”**는 것이다. 흔히 하는 실수가 전역 타이머 하나를 두고 새 알림이 올 때마다 리셋하는 건데, 그러면 알림들이 제각각 3초를 못 채우고 한꺼번에 사라지거나 꼬인다. 각 아이템이 자기 타이머를 들고 있어야 한다.

const MAX = 5, TTL = 3000;

function onImage(data) {
  const box  = document.getElementById("notify");
  const item = document.createElement("div");
  item.className = "notify-item";

  const img = document.createElement("img");
  img.src = toPublicUrl(data.img_path);      // (아래 설명) 서버 경로 → 접근 가능한 URL
  img.onerror = () => remove(item);          // 로드 실패하면 즉시 제거

  const close = document.createElement("button");
  close.textContent = "×";
  close.className = "notify-close";          // 평소 숨김, hover 시 표시(CSS)
  close.onclick = () => remove(item);

  item.append(img, close);
  box.append(item);                          // 최신을 아래에 append → 기존은 위로 밀림

  while (box.children.length > MAX)          // 5개 초과 시 가장 오래된(맨 위) 것 제거
    remove(box.firstElementChild);

  item._timer = setTimeout(() => remove(item), TTL);  // ★ 아이템 개별 타이머
}

function remove(item) {
  if (!item) return;
  if (item._timer) clearTimeout(item._timer);  // 수동으로 닫을 때 타이머도 정리(중복 실행 방지)
  item.remove();
}

닫기(× 클릭)나 로드 실패로 미리 제거할 때 타이머를 꼭 clearTimeout 해줘야 한다. 안 그러면 이미 사라진 요소를 타이머가 또 지우려 하거나, 타이머 콜백이 엉뚱하게 도는 자잘한 버그가 생긴다. × 버튼은 CSS에서 평소엔 숨겨두고 .notify-item:hover .notify-close { display:block } 로 hover 때만 띄우면 된다.

서버가 준 “경로"는 브라우저 URL이 아니다#

메시지의 img_path는 보통 서버 파일시스템 경로(/data/sample.jpg 같은)로 온다. 브라우저는 이 경로로 파일을 못 읽는다. 웹으로 서빙되는 URL로 변환해줘야 한다. 서버가 특정 디렉토리를 특정 URL 접두어로 서빙하고 있다면, 그 접두어로 치환하는 식이다.

function toPublicUrl(p) {
  // 예: 서버의 /data/  디렉토리를 /media/ URL 로 서빙 중이라면
  return p.replace(/^\/data\//, "/media/");
}

이건 프로젝트마다 다르니 “서버 경로 → 서빙 URL” 매핑 규칙을 한 군데 함수로 두는 게 좋다. 이 변환을 깜빡하면 이미지가 전부 깨져서 나온다.. (그리고 onerror로 즉시 제거하게 해두면 깨진 이미지가 화면에 안 남는다.)

테스트 클라이언트 하나면 개발이 편하다#

실시간 기능은 보내주는 쪽(서버/생산자)이 있어야 테스트가 되는데, 그걸 매번 띄우기 번거롭다. 그래서 메시지를 원하는 만큼 쏴주는 작은 파이썬 클라이언트를 하나 만들어두면 개발이 훨씬 수월하다. 인자로 횟수·간격을 받게 했다.

import asyncio, json, sys, websockets

async def main(count, interval):
    uri = "ws://localhost:8764"
    msg = {"msg_type": "image", "img_path": "/data/sample.jpg", "channel": 1}
    async with websockets.connect(uri) as ws:      # 연결은 한 번만 열고 재사용
        for i in range(count):
            await ws.send(json.dumps(msg))
            try:
                print("recv:", await asyncio.wait_for(ws.recv(), timeout=5))
            except asyncio.TimeoutError:
                pass                               # 응답 없어도 계속
            if i < count - 1:                      # 마지막엔 간격 대기 안 함
                await asyncio.sleep(interval)

if __name__ == "__main__":
    count    = int(sys.argv[1])   if len(sys.argv) > 1 else 1
    interval = float(sys.argv[2]) if len(sys.argv) > 2 else 1.0
    asyncio.run(main(count, interval))

1

python ws_test_client.py 10 2   # 2초 간격으로 10번 전송

포인트는 연결을 한 번만 열고 그 위로 반복 전송하는 것. 매 전송마다 새로 connect하면 실제 동작과도 다르고 느리다. 이 스크립트 하나로 “여러 개가 쌓이는지”, “5개 넘으면 오래된 게 빠지는지”, “3초 뒤 사라지는지"를 전부 눈으로 확인했다.

정리#

  • 실시간 “생기는 즉시"는 폴링 말고 WebSocket push. 여러 이벤트는 하나의 소켓 + msg_type 라우팅으로.
  • 공통 소켓 코드 + 페이지별 핸들러는 typeof fn === "function" 가드로 느슨하게 연결.
  • 스택 토스트는 아이템마다 개별 타이머, 수동 제거 시 clearTimeout으로 정리, 초과분은 오래된 것부터.
  • 메시지의 서버 경로는 서빙 URL로 변환해야 하고, onerror로 깨진 이미지 정리.
  • 작은 테스트 클라이언트(횟수·간격 인자, 연결 재사용)를 만들어두면 실시간 개발이 훨씬 편하다.

실시간 알림은 “소켓 열고 그리기"만 생각하기 쉬운데, 실제로 손이 많이 간 건 여러 개가 각자의 수명을 갖게 하는 부분(개별 타이머·정리)이었다. 그리고 테스트 클라이언트 하나 만들어둔 게 이 자잘한 동작들을 검증하는 데 제일 큰 도움이 됐다.
