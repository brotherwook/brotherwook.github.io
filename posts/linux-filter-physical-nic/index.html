[Linux] 목록에서 진짜 물리 NIC만 걸러내기 — docker·veth·wifi 제외

네트워크 설정 UI의 NIC 목록에 docker0·veth·tailscale·wifi 가 잔뜩 떠서, 진짜 유선 물리 인터페이스만 남기는 법. 접두어 블록리스트와 /sys/class/net 기반의 더 견고한 판별, 그리고 필터링하며 딸려온 버그 둘.

목록에 잡동사니가 너무 많다#

네트워크 설정 화면에서 NIC(랜카드)를 고르게 했는데, 목록에 eth0 같은 진짜 유선 카드 말고도 docker0, veth..., br-..., tailscale0, wlan0 같은 게 잔뜩 떴다. Docker 브리지, 컨테이너 가상 인터페이스, VPN, 무선랜.. 사용자가 골라야 하는 건 물리 유선 NIC 하나인데 잡동사니에 파묻힌 것.

그래서 “진짜 물리 인터페이스만” 남기는 필터가 필요했다. 방법은 두 가지인데, 하나는 실용적이고 하나는 더 견고하다.

방법 1: 접두어 블록리스트 (빠르고 실용적)#

가상·무선 인터페이스는 이름 접두어가 대체로 정해져 있다. 그걸 걸러내는 방식.

IGNORE_PREFIXES = (
    "lo", "docker", "br-", "veth", "virbr",   # 루프백 · Docker · 브리지 · 가상 페어
    "tailscale", "wg", "tun", "tap", "zt", "ppp",  # VPN · 터널
    "wl", "wifi",                              # 무선랜
)

def is_ignored(name):
    base = name.split(":")[0]          # eth0:1 같은 alias 는 ':' 앞 원본 이름 기준
    return base.startswith(IGNORE_PREFIXES)

간단하고 대부분 잘 걸러진다. 다만 새로운 가상 인터페이스 종류가 나오면 목록에서 놓칠 수 있다는 게 약점이다. eth0:1 같은 alias는 : 앞의 원본 이름으로 판단해야 한다는 것도 놓치기 쉽다.

방법 2: /sys/class/net 으로 판별 (더 견고)#

이름에 의존하지 않고 커널이 알려주는 정보를 쓰는 방법. 리눅스는 /sys/class/net/<이름>을 심볼릭 링크로 두는데, 가상 인터페이스는 이게 .../devices/virtual/...을 가리킨다.

1
2
3

# virtual 이면 가상(veth, docker, bridge, tun, lo ...) → 제외
readlink -f /sys/class/net/eth0    # /sys/devices/pci.../net/eth0   ← 물리
readlink -f /sys/class/net/docker0 # /sys/devices/virtual/net/docker0 ← 가상

이 한 방으로 docker·veth·bridge·tun·tap·loopback이 한꺼번에 걸러진다. 이름 목록을 관리할 필요가 없어서 새 종류가 나와도 자동으로 잡힌다. 무선은 /sys/class/net/<이름>/wireless(또는 phy80211) 존재로 구분한다.

import os

def is_physical_wired(name):
    path = f"/sys/class/net/{name}"
    # 1) 가상 인터페이스 제외
    if "/devices/virtual/" in os.path.realpath(path):
        return False
    # 2) 무선 제외
    if os.path.exists(f"{path}/wireless") or os.path.exists(f"{path}/phy80211"):
        return False
    return True

개인적으로는 방법 2를 추천한다. 이름 규칙은 배포판·드라이버마다 바뀔 수 있지만, “virtual이냐"는 커널 기준이라 훨씬 안정적이다. 다만 구형 코드가 ifconfig 파싱으로 이름만 들고 있는 상황이면, 우선 방법 1로 막고 점진적으로 방법 2로 옮기는 것도 현실적인 선택이다. (나는 서버·클라이언트 양쪽에 같은 블록리스트를 두는 이중 방어부터 넣고 갔다.)

필터링하면서 딸려온 버그 둘#

필터를 넣을 때, 필터 자체보다 주변 로직에서 문제가 났다. 비슷한 상황이면 같이 점검해볼 만하다.

① 기본 선택값이 걸러질 NIC로 잡힌다. “목록의 첫 번째를 기본 선택"으로 두는 코드가 필터 바깥에 있으면, 걸러져야 할 가상 NIC가 먼저 나올 때 그게 기본값으로 잡힌다. 기본값 대입을 필터 안쪽으로 옮겨야 한다.

② 남는 게 0개일 때 뒤가 터진다. 필터가 너무 세서 표시할 NIC가 하나도 안 남으면, “선택된 NIC로 뭔가 하는” 후속 코드가 빈 값으로 예외를 던진다. 그리고 그 예외 때문에 그 뒤 초기화(예: 다른 설정 로드)까지 통째로 건너뛴다. “빈 목록"을 정상 케이스로 보고 가드를 넣어야 한다.

nics = [n for n in all_nics if is_physical_wired(n)]
default = nics[0] if nics else ""    # 필터 결과에서 기본값, 없으면 빈 값
if default:
    select(default)
# else: 빈 목록도 정상 흐름으로 (뒤 초기화가 안 끊기게)

정리#

  • NIC 목록에서 물리 유선만 남기려면 가상(docker/veth/br/tun/lo)·무선(wl)을 걸러야 한다.
  • 접두어 블록리스트는 빠르지만 새 종류를 놓칠 수 있다. eth0:1 alias는 : 앞 이름 기준.
  • /sys/class/net/<이름>이 virtual을 가리키는지로 보면 이름에 안 기대고 견고하게 걸러진다. 무선은 wireless/phy80211로.
  • 필터 넣을 땐 기본 선택값을 필터 안쪽에서 잡고, 빈 목록을 정상 케이스로 가드.

필터 조건 한 줄보다, 그 필터가 바꾼 “기본값"과 “빈 목록” 처리가 더 자주 사고를 냈다. 목록을 거를 땐 거른 뒤의 흐름까지 같이 봐야 한다는 걸 배운 작업이었다.
